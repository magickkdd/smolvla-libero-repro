Part I

先修：把 VLA 写成一个可计算的问题

不理解目标函数，后面所有架构细节都只是名词。这一部分只做三件事：定义策略、推出训练目标、讲清注意力掩码。

CHAPTER 1

VLA 的问题定义：从观测到动作块

VLA 不是“让大模型聊天”，而是把视觉、语言、本体状态映射成一段连续动作。这个映射的输入输出形状、时间尺度与评测方式，决定了后面每一个设计选择。

1.1 形式化

在时刻 t，机器人收到观测 o_t（多路图像 + 本体状态）和语言指令 ℓ。策略输出未来 H 步的动作块：

π(at:t+H−1∣ot,ℓ)

本项目里 H = chunk_size = 50，动作维度 7（末端三维平移、三维旋转、夹爪），但模型内部统一 pad 到 32 维。LIBERO 控制频率约 20 Hz，所以一个 chunk 覆盖约 2.5 秒。评测时 n_action_steps = 1，即每执行 1 步就重新观测、重新预测；训练时一次监督全部 50 步。

两个“步”不要混

update / step（优化步）：一次梯度更新。本项目 8000 次。action step（控制步）：仿真里执行一次动作。一次 update 用 64 个样本，每个样本含 50 个未来动作；一次评测 rollout 可能走 100–280 个控制步。面试里说“8000 步”必须补“updates”，否则会被理解为控制步。

1.2 为什么是“动作块”而不是单步动作

单步策略 π(a_t | o_t) 在每个控制步都要前向一次大模型；更糟的是，示范数据中相邻动作高度相关，单步回归容易学到“平均动作”，在接触、抓取等多模态处失效。动作块同时解决三件事：

  • 时间抽象：一次预测 50 步，降低推理频率；
  • 多模态表达：整段轨迹作为生成目标，模型可以保留“向左绕”或“向右绕”两种模式，而不是平均成撞桌角；
  • 减少复合误差：开环执行一小段，比每步独立决策更平滑；但开环太长又会失去反馈，所以 n_action_steps 是可调的执行视界。
算一笔账

20 Hz 下，chunk=50 覆盖 2.5 s。若 n_action_steps=50，每 2.5 s 才前向一次，但 2.5 s 内看不到新观测；若 n_action_steps=1，每 50 ms 重规划一次，鲁棒但算力高 50 倍。LIBERO 是准静态桌面操作，论文与本项目都选 1，用算力换成功率与协议一致性；真机高频抓取则常用 5–20 的折中，或 RTC（实时 chunk）做重叠融合。

1.3 训练目标：从最大似然到速度回归

示范数据给出 (o_t, ℓ, a_{t:t+49})。最直接的做法是回归 ‖π(o,ℓ) − a‖²，但当同一观测对应多条合理轨迹时，条件分布的均值可能不是一条可行轨迹。SmolVLA 改用流匹配：不直接回归动作，而是回归“把噪声搬运到动作”的速度场。第 2 章会完整推导；这里先记住结论：

L=𝔼t∼p(t),ε∼𝒩(0,I),a∼𝒟 ‖vθ(xt,t,o,ℓ)−(ε−a)‖2

注意：生成的是整块 50×32 的动作张量，图像与语言只作为条件，不参与生成。这一点常被误解为“模型在生成图像”，面试时要立刻纠正。

1.4 评测指标

LIBERO 的成功率是二值结果的平均：每个任务固定若干初始状态，跑固定步数，环境给出 check_success()。本项目 10 个任务 × 10 个 episode = 100 次 rollout，报告总成功率与 Wilson 置信区间。单看 74% 没有意义，必须同时说清：任务数、每任务 episode 数、初始状态是否固定、n_action_steps、图像分辨率、是否 hard reset。第 16 章会解释为什么 100 个样本只能分辨“大差异”。

面试官想看什么

你说“成功率 74%”时，他在等三个补充：多少个 episode、置信区间、和论文是否同协议。主动给出这三点，可信度立刻不同。若只报一个百分数，会被认为是“跑了个脚本”。

练习 1.1 · 概念

如果把 n_action_steps 从 1 改成 10，训练完全不变，评测成功率通常会怎样变化？为什么？请给出两个方向相反的机制。

参考答案

可能下降：执行 10 步开环期间没有新观测，初始状态或接触误差会累积；LIBERO 的抓取对末端位置敏感，开环越久越容易偏。可能上升：预测的 50 步在训练分布内是连贯的，减少重规划可以避免每步独立采样带来的抖动与“犹豫”；同时推理次数降为 1/10，评测吞吐提高。净效应取决于任务动态与控制频率，必须实验。论文在仿真里选 1，是在“准确率优先”的设定下做的选择，不代表真机最优。

CHAPTER 2

流匹配：10 步把噪声搬到动作

这一章只讲 SmolVLA 真正用到的那一小块：线性插值路径、速度目标、欧拉积分、时间采样。推导完整但不引入随机微分方程。

2.1 从“生成模型”到“学一个速度场”

设真实动作块 a ∈ R^{50×32}，噪声 ε ∼ N(0,I)。我们构造一条从噪声到动作的直线路径。本项目采用 NOISE_AT_ONE 约定：t=1 是纯噪声，t=0 是干净动作。

xt=tε+(1−t)a,t∈[0,1]

对 t 求导，得到沿路径恒定的速度：

vt=dxtdt=ε−a

于是训练目标变成：给定 x_t、t 和条件 (o,ℓ)，预测 ε − a。这是一个回归问题，不是对抗训练，也没有 ELBO。网络只需要学会“在这个噪声水平下，往哪个方向走、走多快”。

推导 · 为什么速度目标成立

把 x_t 的定义代入：x_t = a + t(ε−a)，所以 ε − a = (x_t − a)/t。给定 (x_t,t) 时，a 的条件期望是 E[a|x_t]，而条件速度的期望满足 E[ε−a | x_t] = (x_t − E[a|x_t])/t。最小化 MSE 的最优解正是这个条件期望。也就是说，网络学到的不是某一条固定轨迹，而是“从当前点到动作流形的平均方向”；多模态由 t 较大时的分支结构保留，随着 t→0 收敛到某个模式。严格的一般性证明需要连续性方程，面试不必展开，但要知道“MSE 最优解 = 条件期望速度”这句话。

2.2 训练算法

for (o, l, a) in loader:                 # a: [B, 50, 32]
    eps = randn_like(a)                  # 标准高斯
    t   = Beta(1.5, 1.0).sample([B])     # 偏向 t=1（高噪声）
    t   = t * 0.999 + 0.001              # 避开端点数值问题
    x_t = t[:,None,None]*eps + (1-t)[:,None,None]*a
    v   = eps - a
    pred = policy(o, l, x_t, t)          # [B, 50, 32]
    loss = masked_mse(pred, v, valid_steps)

时间采样用 Beta(1.5, 1.0)，均值 1.5/2.5 = 0.6，概率质量偏向高噪声端。直觉：高噪声时全局形态未定，学习信号更强；低噪声时只剩细节，且动作块在 t≈0 附近几乎相同，过多采样会浪费容量。这是一个可消融的设计点，面试若问“为什么不是均匀采样”，答“经验上高噪声更难、梯度更有信息量，Beta(1.5,1) 是论文/实现的选择，可用均匀分布做对照”。

2.3 推理：前向欧拉积分

从 x_1 = ε 出发，沿速度场走 N=10 步，每步 Δt = −1/N：

xt−Δt=xt−Δt⋅vθ(xt,t,o,ℓ)

注意符号：因为 t 从 1 减到 0，Δt 是负数，所以代码里等价于 x ← x - (1/N)·v。如果误写成 x + (1/N)·v，动作会朝噪声方向爆炸——这是实现流匹配最常见的 bug。项目代码在 euler_integrate 里按约定处理方向，切换 NOISE_AT_ZERO 时会翻转符号，读代码时要确认约定。

一维手算

设 a=1.0，ε=−0.5，t=0.7。则 x=0.7×(−0.5)+0.3×1= −0.05，v=ε−a=−1.5。走一步 Δt=−0.1：x ← −0.05 − 0.1×(−1.5)=0.10。解析解在 t=0.6 是 0.6×(−0.5)+0.4×1=0.10，完全一致。线性路径下，只要速度预测准确，欧拉积分没有离散误差；现实中的误差来自网络预测，而不是积分格式。

练习 2.1 · 推导

若改用 NOISE_AT_ZERO（t=0 是噪声），写出 x_t、速度目标与欧拉更新式，并说明代码里为什么需要翻转符号。

参考答案

x_t=(1−t)ε+t a，v_t=a−ε，积分从 t=0 到 1，Δt=+1/N，x←x+Δt·v。两种约定描述同一条几何路径，只是参数化方向相反；若把 NOISE_AT_ONE 训练出的速度直接喂给 NOISE_AT_ZERO 的积分器而不翻转符号，就会沿反方向走，等价于 x←x−Δ·v 的符号错误。RTC 处理器内部固定用 NOISE_AT_ONE 语义，所以适配层会做 1−t 与速度取反。

CHAPTER 3

Transformer、RoPE 与 prefix-LM 掩码

SmolVLA 的“魔法”不在新算子，而在两路 token 共享一次注意力调用、却用一张掩码精确控制谁能看谁。把这张掩码讲清楚，架构就通了。

3.1 最小必要机制

多头注意力对每个 token 计算 Q,K,V，用 softmax(QKᵀ/√d + mask)V 聚合。掩码里 −∞ 表示禁止。SmolVLM2 的文本骨干使用 RoPE（旋转位置编码）：把 Q/K 的每对维度视为二维向量旋转一个与位置成正比的角度，因此注意力只依赖相对位移 i−j，外推到更长序列时比绝对位置编码更稳。

本项目还涉及 GQA（分组查询注意力）：Q 的头数多于 K/V 的头数，多个 Q 头共享一组 K/V，减少 KV cache 显存。动作专家沿用与 VLM 相同的 head 维度，才能把两路的 Q/K/V 在序列维拼接。

3.2 一张掩码，三种可见性

SmolVLA 不用标准的因果掩码，而用 openpi/big_vision 的 cumulative mask：每个 token 有一个 att_mask（0 或 1），先做累加，再令 token i 能看见 j 当且仅当

cj≤ci,ci=∑k≤imk,mk∈{0,1}

实现里同时乘上 pad_j & pad_i，把 padding token 屏蔽。这个设计的含义是：att_mask=0 的连续片段构成一个双向可见的块；每遇到一个 1，就开启一个新的、只能看前面块和自身块内历史的片段。

为什么 state 的 att_mask 是 1？

源码注释写得很直白：“Set attention masks so that image and language inputs do not attend to state or actions.” 把状态单独开一个块，既让状态能看到完整视觉/语言上下文，又保证图像/语言 token 的表示不被状态污染。副作用是状态也不能看动作（本来就不该看）。这个小细节是区分“读过代码”与“只看过论文图”的分水岭。

3.3 两路 token 如何共享一次注意力

在自注意力层，代码把 VLM 与专家的 Q/K/V 沿序列维拼接，做一次 attention，再按长度切回两路。由于掩码规定前缀看不到后缀，VLM 一侧的计算与“只跑前缀”等价；专家一侧则同时获得前缀信息与动作历史。在去噪阶段，VLM 输入是 None，只有专家流进入计算，但它会读取预填充时缓存的前缀 K/V，所以“自注意力层”实际上也完成了一次跨模态读取。

交叉注意力层则不同：专家的 Q 来自自身，K/V 从前缀缓存读取后，再用专家的 k_proj/v_proj 重新投影到专家空间；专家位置 id 会被减去最小值，使其从 0 开始——因为交叉注意力只关心专家内部的相对顺序。前缀预填充时，所有层都走自注意力路径以填满 KV cache；只有在去噪阶段才按 layer_idx % 2 交替走 SA / CA。这一点在源码里由 fill_kv_cache 条件控制。

3.4 KV cache：为什么推理能快 3–4 倍

前缀（≤177 token）在 10 次去噪中不变，可以只算一次，把每层的 K/V 存下来。之后每步只输入 50 个动作 token，注意力代价从 O((L+50)²) 降为 O(50² + 50L)。粗略估算（单层、忽略常数）：

方式每步注意力元素数10 步合计相对开销
不缓存（每步重算全序列）(177+50)² ≈ 51,529515,2903.56×
缓存前缀（只算后缀）50² + 50×177 ≈ 11,35031,329 + 113,500 = 144,8291.00×

每步结束后代码调用 past_key_values.crop(prefix_len)，把刚追加的 50 个动作 K/V 丢掉，恢复成纯前缀，供下一步复用。这是“10 步去噪不会让 cache 越滚越大”的关键；忘了 crop 会导致显存随步数线性增长，并在第 10 步报 shape 不匹配。

缓存本身也占显存：每层每路 K/V 为 2 × B × H_kv × L × d_head。对 16 层、5 个 KV 头、64 维、177 token、batch 10，约 16×2×10×5×177×64×2 bytes ≈ 36 MB（fp16），可以忽略；真正占显存的是 450M 权重与激活。面试若问“KV cache 有什么代价”，答“显存随层数、KV 头数、序列长度线性增长；对长上下文/大 batch 才显著，本项目前缀不到 200 token，不是瓶颈”。

练习 3.1 · 掩码

给定 att_mask = [0,0,0,1,1,1]，写出 6×6 可见矩阵中被允许的位置（行 query，列 key），并说明它对应哪种注意力模式。

参考答案

cumsum = [0,0,0,1,2,3]。行 0–2 只能看列 0–2（双向）；行 3 看列 0–3；行 4 看列 0–4；行 5 看列 0–5。即“前 3 个 token 双向 + 后 3 个 token 因果”，正是 prefix-LM。若把第 4 个 token 的 mask 改成 0，则前 4 个变成双向块，后 2 个因果。

常见误区

①把 att_mask 当成“是否参与注意力”的开关——不是，它控制的是块边界；真正屏蔽 padding 的是 pad_mask。②以为前缀能看后缀——不能，cumsum 条件保证了这一点。③以为动作之间双向——不能，后一个动作能看到前一个，反之不行，这是自回归生成的结构。④以为去噪时 VLM 又跑了一遍——没有，inputs_embeds=[None, suffix]，只跑专家。

CHAPTER 5

配置系统与一次 update 的全过程

lerobot 用 dataclass + draccus 把 YAML/CLI 映射成强类型配置。理解“配置从哪来、覆盖到哪、何时校验”，你才能解释为什么同一份代码能跑 LIBERO、Aloha 和真机。

5.1 配置的三层来源

  1. 默认值：SmolVLAConfig 的字段（chunk_size=50、num_vlm_layers=16、expert_width_multiplier=0.75…）。

一个真实的坑：覆盖不存在的键不会报错

项目在数据增强实验里想改 policy.image_transforms.tfs，但该键在配置里是一个整体 JSON 对象。用点路径只覆盖子字段时，draccus 可能静默保留默认值，最终得到一个“恒等变换”——你以为开了增强，实际没有。正确做法是整体替换 tfs 字典，并在启动时打印生效的变换列表做自检。这个教训在面试里很值钱：它说明你验过“配置真的生效”，而不是只看 loss 动了。

5.2 一次 update 的步骤

batch = next(loader)                  # 图像 [B,2,3,512,512], state [B,32], action [B,50,32]
batch = preprocessor(batch)           # resize/pad、tokenize、归一化、device
loss, log = policy.forward(batch)     # 采样 t/eps → 前向 → masked MSE
accelerator.backward(loss)            # fp16: GradScaler 先 scale loss
clip_grad_norm_(params, 10.0)
optimizer.step(); scheduler.step(); optimizer.zero_grad()
if step % save_freq == 0: save_checkpoint(...)

冻结策略下，优化器只包含动作专家与 state_proj 的参数（约 100M），VLM 的 350M 只做前向。注意 VLM 仍在 eval() 模式（dropout 关闭），但梯度图不建立，显存主要花在激活上。

5.4 学习率调度：为什么“对齐步数”是硬约束

余弦带 warmup 的形式是

η(s)=ηmin+1+cos(π⋅s−swsd−sw)2(ηmax−ηmin)

本项目 warmup=2000、decay=32000、peak=1e-4、min=2.5e-6。在第 8000 步，进度 (8000−2000)/(32000−2000)=0.2，余弦因子 (1+cos(0.2π))/2≈0.905，学习率约 9.1e-5，仍接近峰值。若把 decay_steps 设成 8000，则最后几十步学习率会掉到 2.5e-6，模型几乎停止更新；这不是“训练完了”，而是“调度器提前收尾”。项目把“scheduler 步数与 --steps 显式对齐”写进纪律，就是为了避免这种静默空转。

5.5 checkpoint 与断点续训

一个完整 checkpoint 目录包含 pretrained_model/（权重 + config.json + processor 四个文件）与 training_state/（优化器、调度器、GradScaler、RNG、采样器偏移）。只恢复权重而不恢复优化器，会让 Adam 动量清零、学习率从头开始，表现为 loss 突然跳变。项目的续训命令同时传 --resume=true 与 --config_path=.../checkpoints/000008000/pretrained_model，前者恢复训练状态，后者指定策略配置与权重。

在 Kaggle 上，checkpoint 还要对抗“会话被回收”：每 1000–2000 步保存，并把 pretrained_model 与 training_state 全量上传到私有 HF 仓库的 checkpoints-backup/。下次启动扫描 Hub 上最大累计步数，自动计算剩余步数。这里最容易犯的错是只上传顶层文件、漏掉子目录，导致加载时报 “Missing processor artifact 'tokenizer'”。

CHAPTER 6

评测入口：协议、批处理与统计

训练决定上限，评测决定你能否把上限讲清楚。本章跟踪 lerobot-eval 的一次完整调用，并给出置信区间的正确算法。

6.1 评测命令与参数语义

lerobot-eval \
  --policy.path=outputs/m1_base_libero/checkpoints/008000/pretrained_model \
  --env.type=libero --env.task=libero_spatial \
  --eval.batch_size=10 --eval.n_episodes=10 \
  --policy.n_action_steps=1 --policy.num_steps=10 \
  --output_dir=outputs/eval_m2

关键语义：batch_size=10 表示同时开 10 个并行环境（不是 10 个任务）；n_episodes=10 表示每个任务跑 10 个 episode。LIBERO 有 10 个任务，所以总共 100 次 rollout。n_action_steps=1 覆盖策略默认的 50，保证“每执行一步就重规划”。

6.2 并行环境如何绑定初始状态

每个子环境在构造时拿到 episode_index，并令 init_state_id = episode_index；reset 时从该任务的初始状态文件里取第 init_state_id % len(states) 个状态，然后 init_state_id += n_envs。这样 10 个并行环境在第一轮分别用 0–9 号初始状态，第二轮用 10–19 号，既避免重复，又保证同一任务的所有 episode 覆盖不同初始布局。若 n_envs 与任务数不整除，最后一个 batch 会少跑几个 episode，脚本按 n_episodes 截断。

reset 之后还有 num_steps_wait=10 步的零动作预热。原因是仿真重置后物体可能轻微悬空或相交，直接执行策略动作会得到非物理的初始观测；空转 10 帧让物体落稳。这个细节会显著影响可复现性，面试若问“为什么你的评测和别人的差几个点”，先查预热步数与初始状态。

6.3 成功判定与聚合

每个控制步调用 env.check_success()，一旦成功就 terminated=True；达到套件最大步数（spatial 280、goal 300、libero_10 520）则截断。评测脚本记录每个 episode 的 success、seed、task，最后写 eval_info.json，包含 aggregated.pc_success、per_task 与逐 episode 明细。项目把 100 个 rollout 视频也一并归档，便于失败模式分析。

6.4 Wilson 区间：公式、复算与修正

二项比例的 95% Wilson 区间为

p^+z22n±zp^(1−p^)n+z24n21+z2n

代入 p̂=0.74, n=100, z=1.96：中心 0.7311，半宽 0.0848，得到 [64.6%, 81.6%]。归档报告写的 [63.0%, 83.2%] 比标准 Wilson 更宽，可能是用了带连续性修正或另一种近似；无论原因，面试应报可复算的值，并说明方法。若被问“为什么不用正态近似”，答“n=100、p 不接近 0/1 时两者接近，但 Wilson 在极端比例（如 3/10）更稳，且不会越界”。

单任务 3/10 的区间有多宽

p̂=0.3, n=10 的 Wilson 区间约 [10.8%, 60.3%]。也就是说 spatial_5 的 30% 与 spatial_1 的 100% 之间的差距，在 10 个样本下依然可能是噪声。不要用单任务排名做“模型能力”结论；要做改进实验，至少把该任务加到 30–50 个 episode，或跨 seed 汇总。

7.2 fp16 迁移为什么不是一行开关

T4 的 Tensor Core 支持 fp16，但不支持 bf16。直接把 torch_dtype="bfloat16" 改成 "float16" 并不够：SmolVLM2 的权重在加载时若以 bf16 存储，转 fp16 可能溢出；更稳的做法是先把权重 cast 成 fp32 保存，训练时用 accelerator.mixed_precision=fp16，让前向/反向的矩阵乘走 fp16、参数更新保留 fp32 master weights，并由 GradScaler 动态放大损失防止下溢。

代价是显存比 bf16 略高、数值范围更窄，长训练可能出现 loss spike。项目里观察到 loss 从 1.14 平滑降到约 0.5，没有出现需要回滚的尖峰；但这不意味着 fp16 永远安全，面试应补一句“若出现 NaN，先查 GradScaler 的 scale 是否持续下降，再查 attention softmax 是否有全 -inf 行”。

CHAPTER 8

VLM 骨干与 token 预算

SmolVLA 的第一个关键决策是“把视觉 token 压到 64/帧”。这不是工程小技巧，而是让 450M 模型能在消费级 GPU 上训练/推理的前提。

8.1 从像素到 token

输入图像先 resize 到 512×512（评测时环境给 256×256，再放大），SigLIP 以 patch 16 切成 32×32=1024 个 patch。若直接送进 LLM，每帧 1024 个 token，两路相机就是 2048，加上语言与 50 个动作 token，序列长度超过 2100，注意力成本与 KV cache 都会爆炸。SmolVLA 用 pixel shuffle 把相邻 4×4 个 patch 的通道重排成一个 token，得到 1024/16=64 个视觉 token/帧。论文的说法是“从约 1000 降到 64”。

8.2 为什么只取前 16 层

SmolVLM2-500M 的文本骨干有 32 层（SmolLM2-360M 量级），SmolVLA 只保留前 16 层，并在其上接同样 16 层的动作专家。理由有三：①动作预测不需要完整的语言推理深度，浅层已包含足够的视觉-语义对齐；②层数直接决定训练/推理成本，16 层让 10 步去噪可控；③与专家层数一一对应，便于“同层 SA/CA”交错。这个选择是论文的实现细节，不是架构公理；面试若问“为什么不是 32 层”，答“消融上没有证据表明越多越好，16 层是精度/延迟的折中，且与专家层对齐”。

动作专家（16 层，720 宽）~100M是把前缀条件转成动作速度场
state_proj / action_in_proj / action_out_proj~1M是状态与动作的模态对齐

总计约 450M，可训练约 100M。冻结的工程收益：优化器状态从 450M×12B≈5.4GB 降到 100M×12B≈1.2GB，激活也只需为专家保留梯度；算法收益：在 1693 条示范上，全量微调 450M 极易破坏 VLM 的语义先验，冻结相当于强正则。

如果面试官问“为什么不 LoRA”

LoRA 冻结原权重、只学低秩增量，显存更省、可多任务切换；但 SmolVLA 的官方 preset 是“冻结骨干 + 全量训练专家”，本项目优先复现官方配方，没有引入 PEFT 变量。若要做 LoRA 对照，应保持数据、步数、评测协议一致，并注意 LoRA 的 rank/alpha 会改变有效学习率；这不是“更先进”，而是另一个权衡。项目把 LoRA 列为 M3 候选，而不是已完成的结论。

8.4 前缀的组装顺序

源码的顺序是：两路图像 → 语言 token → 状态 token。图像与语言共享 att_mask=0 的双向块；状态以 att_mask=1 插在最后。所有 embedding 在进入 Transformer 前乘以 √d（图像与语言都做了），这是 openpi 的惯例，用来平衡 embedding 与位置/模态的尺度。若漏掉这一步，视觉 token 的范数远小于语言 token，注意力会被语言主导——是一个不易察觉但会影响收敛的实现细节。

CHAPTER 9

动作专家：一个更窄的 Transformer

动作专家不是“另一个 VLM”，而是与 VLM 同层数、同 head 布局、但 residual 宽度只有 0.75 的并行流。它没有词表、没有图像输入，只吃“噪声动作 + 时间步”。

9.2 为什么要“交错”而不是每层都做两种注意力

动作 token 需要两类信息：①动作之间的时序一致性（自注意力）；②与图像/语言/状态的 grounding（交叉注意力）。若每层都做 SA+CA，参数与延迟翻倍；若只做 CA，动作之间无法协调，chunk 会抖动。隔层交错是一个性价比很高的归纳偏置：偶数层先在本流内整合，奇数层再去读前缀，下一层再整合。源码里 self_attn_every_n_layers=2 就是这个意思。

一个容易被追问的实现细节

“0.75 倍”主要缩放 residual/MLP 宽度（hidden_size=720），但注意力头的 head_dim 必须与 VLM 保持一致，否则两路 Q/K/V 无法在序列维拼接。源码在构造专家时复制了 VLM 的 text config，只改 hidden_size 与 intermediate_size，保留 head 布局；交叉注意力层还把 k_proj/v_proj 的输入维改成 VLM 的 KV 维，输出维改成专家的 KV 维。面试若问“专家宽度不同怎么做 cross-attn”，答“Q 从专家来，K/V 从前缀缓存来，经专家自己的 k/v 投影对齐到专家的 head_dim；不是直接拿 VLM 的 K/V 做点积”。

9.3 预填充与去噪的两种模式

预填充：输入是完整前缀，所有 16 层都走自注意力路径（fill_kv_cache=True），把每层的 K/V 写入 cache。注意：即使某层在去噪时是 CA 层，预填充也必须用 SA 路径算出它的 K/V，否则 CA 层没有可读的缓存。

去噪：输入只有 50 个动作 token。偶数层走 SA，读取 cache 中的前缀 K/V 并追加当前动作 K/V；奇数层走 CA，读取 cache、经专家 k/v 投影后做注意力。每步结束 crop(prefix_len)，丢弃本步追加的动作 K/V，保证下一步从干净前缀开始。

9.4 参数量与计算量

专家的参数主要来自每层的 Q/K/V/O 与 MLP。粗略地，宽度 720、16 层，参数量在 100M 量级，与论文口径一致。计算量上，预填充是一次性的（16 层 × 177 token），去噪是 10 次 ×（8 层 SA + 8 层 CA）× 50 token。与“每步重算 227 token”相比，缓存把前缀的二次项摊销掉，这是 10 步去噪可行的关键。

前向、损失与形状：把一次训练算清楚

面试里最容易被追穿的是形状与分母。本章以 B=32、两路相机、语言 48、动作 50×7 为例，逐张量走一遍，并解释为什么 loss 的分母不是 50×32。

10.1 输入张量

10.2 前缀与后缀

前缀：每路图像经 SigLIP + pixel shuffle 得到 64 个 token，投影到 960 维；语言 embedding 也是 960 维；状态经 state_proj 投到 960 维，作为 1 个 token。三者拼接后形状 [32, 177, 960]（图像 128 + 语言 48 + 状态 1）。不足 177 时在尾部 pad 0，pad_mask=0。

后缀：噪声动作 [32,50,32] 先经 action_in_proj 投到 720 维；时间 t 用正弦位置编码扩展到 720 维，与动作 embedding 拼接成 1440 维，再经两层 MLP（中间 SiLU）压回 720 维。结果形状 [32,50,720]。时间信息不是加到每个 token 的标量，而是通过 MLP 融合，这一点与 DiT 的 AdaLN 不同。

10.3 掩码、位置与输出

把前缀与后缀拼成总序列（≤227），att_mask 为“128 个 0 + 48 个 0 + 1 个 1 + 50 个 1”，pad_mask 为真实 token 的掩码。位置 id 用 cumsum(pad_mask)-1，保证 padding 不占位置；后缀位置从前缀有效长度之后继续。输出取最后 50 个位置（suffix_out[:, -50:]），先 upcast 到 fp32，再经 action_out_proj 得到 [32,50,32]，最后切前 7 维。

为什么输出要 upcast 到 fp32？

源码注释写的是 “Original openpi code, upcast attention output”。fp16 下动作回归的最后一层对数值很敏感，upcast 后再做线性投影与 MSE，可以减少小数值下溢与梯度噪声。这是一个几乎不增加成本的稳定化技巧；面试若问“fp16 训练怎么稳”，这是可以具体说的一条。

10.4 loss 的掩码与分母

源码的顺序是：先算逐元素 MSE [B,50,32]，按真实动作维度切片 [B,50,7]，再乘 ~action_is_pad，最后除以“有效步数 × 7”。注意切片长度不是硬编码的 7，而是从输出特征里取 action_feature.shape[0]（LIBERO 为 7，Aloha 为 14，因此同一份代码能适配不同机器人）：

losses = losses[:, :, : action_feature.shape[0]]   # 去掉 pad 的 25 维（LIBERO: 7）
losses = losses * (~actions_is_pad)[..., None]     # 去掉 episode 末尾
losses = losses[:, :, : self.config.max_action_dim]  # 32 维上界，此处为 no-op
num_valid = ((~actions_is_pad).sum() * losses.shape[-1]).clamp_min(1)
loss = losses.sum() / num_valid
分母手算

B=32，每条样本 50 步，其中 3 条样本各有 47 步是 padding，其余 29 条全有效。有效步数 = 32×50 − 3×47 = 1600 − 141 = 1459，分母 = 1459×7 = 10213。若错误地用 losses.mean()（分母 32×50×7=11200），有效动作会被稀释约 9%；若连 32 维一起平均（分母 32×50×32=51200），有效维度会被稀释到 1/4.57，相当于把学习率降到 22%。

为什么 padding 只发生在 episode 末尾？因为第 t 帧的 50 步窗口可能越过 episode 终点，数据集读取器用 delta_window 把越界索引钳到边界，并标记 action_is_pad=True。若不 mask，模型会在“示范结束后的重复帧”上学习静止动作，污染终止行为。

日志里的 loss 可能不是你以为的 loss

loss_dict["losses_after_forward"] 是在“切维度、mask”之前算的均值，只用于观察趋势；真正反传的是 loss_dict["loss"]。如果面试官问“你的 loss 曲线为什么和论文不可比”，先确认口径：是否含 padding、是否含 32 维、是否 fp32。项目报告的 1.14→0.5 是训练日志口径，不应与论文的另一口径直接相减。

CHAPTER 11

推理：预填充、10 步去噪与动作队列

训练是一次前向，推理是“1 次预填充 + 10 次后缀前向”。把这条链路讲清楚，你就能回答延迟、缓存、RTC 与部署的所有追问。

11.1 调用链

select_action(batch)
  └─ if queue empty:
       predict_action_chunk(batch)
         ├─ embed_prefix(images, lang, state)          # [B,177,960]
         ├─ vlm_with_expert.forward(prefix, None)      # 填 KV cache
         ├─ euler_integrate(denoise_step, noise, 10)
         │    └─ 每步: embed_suffix(x_t, t)
         │             forward([None, suffix], cache)
         │             crop(prefix_len)
         └─ 返回 [B,50,7]
  └─ queue.extend(chunk[:n_action_steps])
  └─ return queue.popleft()

11.2 10 步去噪在算什么

第 k 步的输入是当前动作估计 x_t 与时间 t=1−k/10。网络输出速度 v，积分器更新 x ← x − 0.1·v。注意：每一步都要重新编码后缀（因为 x_t 变了），但前缀只编码一次。这就是为什么“动作 token 只有 50 个”仍然需要 10 次 Transformer 前向，而不是 1 次。

如果 n_action_steps=1，下一个控制步会重新观测、重新预填充、重新 10 步去噪；前缀的图像编码与 KV 填充也被重复。评测的算力主要花在这里。若 n_action_steps=50，同一 chunk 执行 50 步，预填充摊销到 50 个控制步，但开环误差累积。这个权衡是面试高频题。

11.3 延迟预算：项目没测的部分要诚实

本项目没有在 T4 上做端到端延迟基准，只记录了评测吞吐（eval_ep_s）。因此不要编造“单次推理 30ms”。可以给出的结构性判断是：450M 模型、10 步去噪、每步 50 个后缀 token，在 T4 上不可能稳定达到 20 Hz 的单步闭环；LIBERO 评测是离线仿真，不受实时约束。真机部署需要至少一项优化：减少 num_steps（精度换速度）、torch.compile、批量/异步推理、动作块执行（增大 n_action_steps）、或 RTC 重叠。

11.4 RTC：实时 chunk 的直觉

动作块之间会出现“接缝”：上一块执行到第 10 步时，新块从当前观测重新预测，前几步可能和旧块不一致，导致抖动。RTC（Real-Time Chunking）把上一块剩余的动作作为软约束，在去噪时引导新块的前缀部分靠近旧块，从而平滑过渡；同时允许推理延迟 inference_delay，用旧块覆盖延迟期间的动作。SmolVLA 的实现支持 supports_rtc=True，但本项目 rtc_config=None，未启用。面试若问“RTC 解决什么”，答“不是提高单步精度，而是解决异步推理下的块间不一致与延迟补偿”。

12.2 delta_timestamps：动作窗口的定义

训练时 delta_timestamps 给动作列配置 [0, 1/20, 2/20, …, 49/20]，给观测列配置 [0]。读取器以当前帧为锚点，计算未来 50 帧的绝对索引；若越过 episode 末尾，delta_window 会把索引钳到 episode 的最后一帧，并把对应位置标记为 *_is_pad=True。所以 padding 不是零，而是“重复最后一帧”，再由 mask 在 loss 里剔除。若忘了 mask，模型会学到“任务完成后保持静止”。

推导 · 为什么窗口要按时间而不是按帧号

数据集的 fps 可能因采集设备不同而变化。若直接写“未来 50 帧”，在 10 fps 与 30 fps 上对应的时间跨度差 3 倍，动作块的物理意义就变了。配置 1/fps 的 delta 让窗口始终覆盖 2.5 秒；LeRobot 在读取时把 delta 换算成帧索引，并在 episode 边界做钳位。这也是跨数据集混训时必须统一 fps 的原因。

12.3 归一化：统计量从哪来、存到哪

策略的 normalizer 用数据集统计量把 state/action 映射到零均值、单位方差（或分位数区间）。统计量在训练开始时从数据集计算，随 checkpoint 一起保存为 processor 配置；评测时加载同一份统计量，不能用评测集重新计算，否则等于泄漏。图像通常不做数据集级标准化，交给视觉编码器自身的归一化；若做了，也要保证训练/评测一致。

一个常被忽略的细节：动作的第 7 维是夹爪，取值可能是 {-1, +1} 或 [0,1]。用 MEAN_STD 把它标准化后，二值性被破坏，但模型仍能学；若用 QUANTILES 并配合反变换，夹爪会更稳定。LIBERO 的夹爪动作在仿真里是连续值，本项目沿用官方 MEAN_STD。

12.4 语言与图像

语言来自 tasks.jsonl 的 instruction，经 SmolVLM2 的 tokenizer 截断/补齐到 48。LIBERO 的指令很短（如 “pick up the black bowl …”），48 足够；若换成长指令数据集，需要提高上限并重新评估 token 预算。

图像在 __getitem__ 里可选地做随机增强（亮度、对比度、饱和度、色调、裁剪、旋转等），再 resize 到 512。增强是在线、逐样本发生的，不是离线写回磁盘；因此同一帧在不同 epoch 会看到不同增强。这提高了数据效率，但也让“训练/评测分布”出现差异——评测不做增强，必须保证 resize 与归一化一致。

13.2 reset 的三件事

  1. 选初始状态：init_state_id = episode_index，reset 时取 init_states[id % len]，然后 id += n_envs。这保证并行环境不重复、跨 batch 覆盖不同布局。
  2. 预热：num_steps_wait=10 步零动作，让物体落稳。硬 reset 会重建仿真场景，软 reset 跳过重建但可能保留物理状态；两者观测分布不同，不能混用。
  3. 设置控制模式：relative/absolute 在 reset 后写入 controller 的 use_delta。训练数据是用哪种模式采集的，评测就必须用哪种，否则动作尺度完全错位。

13.3 为什么评测要 n_action_steps=1

这是与论文仿真协议对齐的选择：每执行一个动作就重新观测、重新预测，最大化闭环反馈。代价是推理次数是“执行整块”的 50 倍。若为了省时间改成 50，成功率可能上升（更连贯）也可能下降（开环误差），而且与论文不可比。面试时应明确：“我报告的是 n=1 协议；若换 n，需要重新标定，不能直接和论文数字比。”

常见不可比因素清单

14.2 DDP 的实际加速比

双卡理想是 2×，实测约 1.9×。损失来自：每步 allreduce 的通信、数据加载与视频解码的串行段、以及每张卡 batch 减半后 kernel 利用率略降。用 torchrun --nproc_per_node=2 启动，accelerate 负责把 batch 切分到两个进程、把梯度求平均。注意：有效 batch 翻倍后不应盲目把学习率翻倍；官方配方是 bs64 + 1e-4，本项目直接沿用，避免引入第二个变量。

14.3 fp16 下的四个稳定化措施

  • GradScaler：动态放大 loss，防止 fp16 梯度下溢；若连续溢出会自动缩小 scale，日志里应监控。
  • 梯度裁剪：裁剪到 10.0，限制偶发大梯度。
  • 输出 upcast：动作头输出转 fp32 再算 loss。
  • 避开端点：时间 t 限制在 [0.001, 0.999]，避免 1/t 类数值问题（若实现里出现）。

若出现 loss NaN，排查顺序：①GradScaler 的 scale 是否持续下降；②attention 是否有整行被 mask（softmax 全 -inf）；③归一化后的动作是否有极端值；④学习率是否在 warmup 前就过大。不要一上来就“换 bf16”，T4 上没有这个选项。

CHAPTER 15

数据增强消融：如何不把结论做废

“加了增强，成功率涨了 4 个点”这句话，在 100 个 episode 上很可能只是噪声。本章给出可辩护的消融设计。

15.1 混淆变量：施加密度

lerobot 的图像增强配置允许 max_num_transforms、random_order、每个变换的 weight 与 p。如果 A 组每样本随机施加 1 个变换、B 组施加 3 个，那么差异既包含“有没有增强”，也包含“增强多强”。正确做法是固定 max_num_transforms 与采样概率，只切换“变换池是否为空/是否启用”，或者做强度阶梯（0/1/2/3 个）而不是二值对比。

项目里踩过的坑

用点路径覆盖 policy.image_transforms.tfs 的子键时，配置没有真正替换，训练跑完才发现增强是恒等变换。教训：启动时打印生效配置，并做一次单样本可视化，确认像素真的变了。仅看 loss 曲线无法判断增强是否生效。

15.2 样本量与功效

两比例检验的近似样本量：

n≈(z1−α/2+z1−β)2[p1(1−p1)+p2(1−p2)](p1−p2)2

以 p1=0.74, p2=0.84, α=0.05, power=0.8 代入：n≈257/臂。本项目每臂 100 个 episode，只能以约 40% 的功效检测 10 点差异；若真实差异是 5 点，功效更低。因此“增强 +4 点”不应作为定论，只能作为“值得扩大样本的迹象”。

15.3 配对设计能省样本

如果两臂使用完全相同的初始状态与评测顺序，就可以做配对比较（McNemar 检验），而不是独立两比例。配对能消掉“任务难度”这个大头方差：同一初始布局下，A 成功 B 失败 / A 失败 B 成功 的不一致对数才是信号。代价是要控制评测顺序与随机种子，且两臂必须都能复现同一初始状态。

CHAPTER 16

评测统计：把 74% 说成一个可信的结论

这一章把“成功率”拆成估计、区间、配对与多重比较。目标不是让你变成统计学家，而是让你在面试里不被一个百分数问倒。

16.1 点估计与区间

100 次独立 rollout 的成功次数服从二项分布。点估计 74/100=0.74；95% Wilson 区间 [0.646, 0.816]。解释：如果重复同样的 100 次评测很多次，约 95% 的区间会覆盖真实成功率。它不表示“真实成功率有 95% 概率落在区间内”（贝叶斯语境才这么说）。

16.2 单任务比较要非常小心

10 个任务各 10 个 episode，单任务成功率的分辨率是 10 个百分点，区间宽度约 50 个百分点。spatial_5 的 30% 与 spatial_1 的 100% 看起来差 70 点，但在 n=10 下并不意外。正确做法：①把单任务结果当作“失败模式线索”，不是能力排名；②对短板任务单独扩到 30–50 个 episode；③看视频定位失败类型（抓空、碰撞、超时、夹爪时机）。

16.3 多重比较

如果你比较 10 个任务并挑“最好的那个”汇报，相当于做了 10 次检验，假阳性率会上升。要么预先指定主指标（总成功率），要么对单任务做 Bonferroni/Holm 校正，要么明确标注“探索性分析”。面试官不一定要求你校正，但你要知道这个问题存在。

17.3 spatial_5 的失败模式假设

从任务语义看，spatial 套件考的是“把物体放到/靠近另一个物体的指定空间关系”，spatial_5 通常涉及更精细的相对位置或遮挡。30% 的可能机制：①深度/尺度估计不稳：单目图像 + 腕部视角，远距离时像素位移小，末端定位误差被放大；②语言 grounding 失败：指令里的空间介词（left/right/behind）没有被可靠绑定到物体；③抓取时机：夹爪闭合晚/早，导致后续放置偏移；④初始状态敏感：10 个初始布局里只有 3 个在训练分布内。

验证方法不是“再训久一点”，而是看视频：统计失败回合里机器人停在哪个阶段（未到达、抓空、掉落、放错位置、超时），再把失败帧与训练帧做分布对比。这一步是 M3 的核心，也是面试时“你如何做 error analysis”的素材。

19.1 五个亮点（按面试价值排序）

  • 评测只覆盖 spatial、单 seed：没有四套件评测，也没有多 seed 方差；结论是“该设定下的基线”，不是“方法的上限”。

  • 没有真机：LIBERO 是准静态仿真，接触、光照、标定误差都没有覆盖；不能声称真机可部署。
  • 没有延迟基准：只记录评测吞吐，没有测单次 chunk 延迟与 20 Hz 闭环可行性。
  • 增强消融不完整：配置曾静默失效，样本量也不足以检测小差异；相关结论只能算探索性。

19.3 STAR 故事一：T4 上的 fp16 迁移

S（情境）
官方 SmolVLA 预设按 bf16 配置，Kaggle 只有 2×T4（SM75），不支持 bf16；直接跑会报错或数值不稳。
T（任务）
在不改变模型结构与超参的前提下，让 450M 策略在 15GB 卡上稳定训练 8000 步。
A（行动）
把 VLM 权重落成 fp32；启用 fp16 autocast + GradScaler；冻结骨干把优化器状态压到 100M；输出转 fp32 再算 MSE；梯度裁剪 10.0；每 2000 步存全状态 checkpoint。
R（结果）
loss 从 1.14 平滑降到约 0.5，无 NaN；双卡 1.9×，4h50m 完成；80 个 rollout 全部产出。

追问预案：“为什么不用 bf16？”——T4 硬件不支持。“fp16 不会溢出吗？”——GradScaler 动态缩放 + fp32 master weights + 输出 upcast；“如果 NaN 怎么办？”——先看 scale 曲线与 attention 全 mask 行。

19.4 STAR 故事二：会话被回收后的续训

S
Kaggle 批处理会话在训练中途被回收，/kaggle/working 保存不完整，checkpoint 缺 processor 文件。
T
不重跑已完成的步数，从最近一个完整 checkpoint 继续到目标步数。
A
改为每 1000 步保存并全量上传 pretrained_model + training_state；启动时递归扫描 Hub 上的累计步数，校验 model.safetensors 与 processor 四件套；残缺目录删除后由 trainer 按标准路径重建；日志打印恢复步数与学习率。
R
最多损失约 35 分钟；多次会话接力后累计到目标步数，没有重复训练。

追问预案：“怎么保证 checkpoint 完整？”——先写临时目录再原子 rename，上传后回读校验；“为什么缺 tokenizer？”——只上传了顶层文件，漏了子目录；“怎么防再次发生？”——启动自检 + 备份命名带全局步数。

19.5 STAR 故事三：把 74% 说成可信结论

S
首版报告只写了“74%”，并引用了错误的 Wilson 区间与“25× 预算差”。
T
让结论经得起统计与协议两方面的追问。
A
复算 Wilson 得 [64.6%, 81.6%]；核对论文微调预算为 100k，改为 12.5×；列出 8 项不可比因素；对 spatial_5 单独做失败模式分析，而不是用总均值掩盖。
R
结论从“我复现了 74%”变成“我在 1/12 预算下建立了可扩展基线，短板在 spatial_5，下一步是预算阶梯与失败诊断”。

这个故事的价值在于展示自我纠错。面试官往往更在意你发现错误后的处理方式，而不是你从不出错。

分层题库：从自我介绍到研究判断

每题给“问法、答法、陷阱”。答法不是逐字稿，而是要点骨架；面试时按对方兴趣展开，不要一次背完。

A 层 · 项目与动机

Q1
用一分钟介绍这个项目。
答法

“我在 2×T4 上用 8000 次更新微调了 450M 的 SmolVLA，在 LIBERO-Spatial 上按 10 任务 × 10 episode 评测，成功率 74%，Wilson 95% 区间 [64.6%, 81.6%]。项目主要解决三件事：T4 无 bf16 的精度迁移、无交互环境下的断点续训、以及评测协议与论文对齐。结论是方法在 1/12 训练预算下仍可用，短板集中在 spatial_5。”

追问钩子

主动留三个钩子：fp16 怎么稳、续训怎么保证完整、74% 与 90% 怎么比。让面试官顺着你准备过的方向问。

陷阱：不要说“我复现了论文 90%”。预算与数据都不同，这句话会被立刻拆穿。
Q2
为什么选 SmolVLA，而不是 OpenVLA 或 π0？
答法
  • 资源约束：只有双 T4 / 消费级卡，7B 的 OpenVLA 与 3.3B 的 π0 微调成本高；450M 能在 15GB 内训练。
  • 架构代表性：SmolVLA 覆盖了当前主流配方（VLM 前缀 + 动作专家 + 流匹配 + 交错注意力），学一个等于理解一类。
  • 可复现性：官方提供 base 权重、LeRobot 集成与 LIBERO 评测脚本，适合做受控实验。
  • 研究空白：小模型在低预算下的失败模式（如 spatial_5）本身值得研究。
陷阱：不要贬低大模型“没用”。正确说法是“在我的资源约束下，SmolVLA 的性价比最高；大模型在泛化与多本体上仍有优势”。
Q3
这个项目里哪些是你做的，哪些是官方代码？
答法

“模型与训练框架来自 LeRobot/SmolVLA 官方；我负责的是：①在 Turing 卡上做 fp16 迁移与显存调优；②搭建可恢复的训练/评测流水线（checkpoint 备份、续训扫描、日志信标）；③按论文协议跑评测并做统计与失败分析；④复现论文结果并定位差距。没有改模型结构，也没有提出新算法。”

陷阱：把官方仓库说成自己写的。面试官很可能读过源码，一问 embed_suffix 就露馅。诚实划分边界反而加分。
Q4
最大的技术难点是什么？
答法

“不是模型，而是状态管理。训练会话随时会被回收，checkpoint 又包含权重、优化器、调度器、processor 四类状态；任何一类缺失都会导致要么从头再来，要么静默换了一个训练过程。我把恢复逻辑做成启动自检：扫描最新完整 checkpoint、校验文件、打印恢复步数与学习率，才把不确定性压下去。”

陷阱：说“调参很难”。调参不是难点，可验证的状态与因果归因才是。

B 层 · 架构

Q5
画出 SmolVLA 的整体架构。
答法

左边是 VLM 前缀：两路图像各 64 token（SigLIP + pixel shuffle）、语言 ≤48、状态 1，共 ≤177，16 层、宽 960，冻结。右边是动作专家：50 个动作 token，16 层、宽 720，隔层 SA/CA，可训练。中间通过共享注意力的 K/V 与交叉注意力连接。输出经 action_out_proj 回到 32 维，取前 7 维。训练用流匹配速度回归，推理 10 步 Euler。

陷阱：把“动作专家”画成独立的第二个 VLM。它没有词表、没有图像输入，只有动作与时间。
Q6
为什么要冻结 VLM？全量微调不是更强吗？
答法
  • 数据：LIBERO 全量 1693 条示范覆盖 40 个任务，但单任务样本很少；全量微调 450M 容易破坏预训练语义先验。
  • 显存：Adam 状态从约 5.4GB 降到 1.2GB，T4 才能放下。
  • 稳定性：小数据 + 大学习率 + fp16，全量训练更容易出现灾难性遗忘与 loss spike。
  • 可迁移：冻结骨干后，动作专家可以独立替换/多任务共享。

但这不是绝对的：数据足够大时，全量或 LoRA 可能更好；这是可消融的假设，不是教条。

陷阱：说“冻结一定更好”。应说“在本项目的数据/硬件约束下更稳”，并给出验证方式。
Q7
动作专家为什么是 0.75 宽？宽度不同怎么做交叉注意力？
答法

0.75 是容量/延迟的折中：动作分布比语言简单，720 维足够；同时减少参数与计算。交叉注意力里，Q 来自专家（720 维），K/V 从前缀缓存读取后，经专家自己的 k_proj/v_proj 投影到专家的 head 布局；head_dim 与 VLM 对齐，保证可以实现。不是直接拿 VLM 的 K/V 做点积。

陷阱：说“专家就是 VLM 的最后几层”。它不是共享权重，而是独立参数、并行流。
Q8
解释 prefix-LM 的注意力掩码。
答法

每个 token 有 0/1 的 att_mask，做 cumsum 得 c；query i 能看 key j 当且仅当 c_j ≤ c_i。图像与语言都是 0，构成一个双向块；状态是 1，开启新块，能看全部前缀；50 个动作都是 1，cumsum 递增，形成因果链。效果是：前缀看不到动作，状态/动作能看到完整上下文，动作之间只能看历史。

陷阱：把 att_mask 说成 padding mask。padding 由另一张 pad_mask 负责。
Q9
为什么视觉 token 要压到 64？为什么只取 16 层？
答法

512×512、patch 16 是 1024 个 patch；两路相机不压缩就是 2048 token，注意力与 KV cache 成本约高两个数量级。pixel shuffle 4×4 把 1024 压到 64，保留粗粒度空间信息，对桌面操作足够。16 层是精度/延迟折中：动作预测不需要完整语言深度，且与专家层一一对应，便于交错 SA/CA。

陷阱：说“64 是论文规定的”。它是实现选择，可以消融（32/128），但要重新调训练预算。

C 层 · 流匹配

Q10
流匹配和扩散的区别是什么？
答法

两者都学“从噪声到数据”的生成过程。扩散学噪声预测 ε，沿随机前向过程的逆过程走，通常需要较多步与特定调度器；流匹配直接学速度场 v=dx/dt，用直线（或近直线）概率路径，训练目标是 ‖v_θ−(ε−a)‖²，推理用 Euler 积分，10 步即可。流匹配更简单、步数更少，但仍是迭代生成，不是一次前向。

陷阱：说“流匹配没有随机性所以是确定性模型”。训练时仍采样 ε 与 t；推理从随机噪声出发，输出仍有多模态。
Q11
在白板上推出流匹配的损失。
答法

设 x_t=tε+(1−t)a，则 dx_t/dt=ε−a。令网络预测 v_θ(x_t,t,o,ℓ)，最小化 E‖v_θ−(ε−a)‖²。对固定 (x_t,t)，最优解是条件期望 E[ε−a|x_t]，即把当前点推向数据流形的平均方向。训练时 t∼Beta(1.5,1)、ε∼N(0,I)，一次采样即可，无需展开时间步。

陷阱：把目标写成 a 或 ε。本项目目标是速度 ε−a；写成别的会与积分器符号不一致。
Q12
10 步去噪能不能改成 1 步？
答法

可以尝试，但会损失精度：1 步相当于假设速度场沿整条路径恒定，而网络预测只在局部准确；误差会直接体现在动作上。常见替代是蒸馏少步模型、consistency 模型、或把 num_steps 降到 3–5 后重训/微调。直接改推理步数而不重训，通常掉点。面试要区分“改配置”和“改训练目标”。

陷阱：说“Euler 是精确的所以 1 步也行”。线性路径下若速度预测完美才精确；现实网络有误差。
Q13
为什么时间采样用 Beta(1.5, 1)，而不是均匀分布？
答法

Beta(1.5,1) 的密度是 1.5t^{0.5}，均值 0.6，偏向高噪声端。高噪声时全局结构未定，预测更难、梯度信息更多；低噪声时动作块差异小，过多采样浪费容量。这是经验选择，不是理论最优；可用均匀分布或 logit-normal 做对照，观察收敛与最终成功率。

陷阱：把它说成“必须”。它是超参，换数据集可能需要重调。

D 层 · 数据与训练

Q14
动作块在数据里怎么取？越界怎么办？
答法

用 delta_timestamps 配 [0,1/fps,…,49/fps]，以当前帧为锚点取未来 50 帧。越过 episode 末尾时，delta_window 把索引钳到 episode 最后一帧，并标记 action_is_pad=True；loss 里用这个 mask 剔除。图像观测只取当前帧（delta 0），不做未来帧。

陷阱：说“padding 补零”。实际是重复边界帧 + mask；补零会让模型学到“动作突然归零”。
Q15
loss 的分母是什么？为什么不是 B×50×32？
答法

先切到真实动作维度 7，再乘 ~action_is_pad，分母是“有效步数 × 7”。因为后 25 维是 padding、episode 末尾的步也是 padding，二者都不应计入。用 B×50×32 会把有效信号稀释约 4.6 倍；用 B×50×7 但仍含 padding 会稀释约 9%（取决于 padding 比例）。

陷阱：只看代码里的 losses.mean()。真正反传的是 masked sum / num_valid，日志里的均值可能只是观测指标。
Q16
归一化的统计量会不会泄漏？
答法

统计量在训练集上计算，随 checkpoint 保存；评测加载同一份，不用评测数据重算。若在评测时用当前 batch 的均值方差，就是泄漏，而且会让不同 batch 的尺度漂移。图像若做数据集级标准化也一样，训练/评测必须共用配置。

陷阱：说“归一化只是预处理，不影响泄漏”。统计量是数据信息，用测试集算就是泄漏。
Q17
双卡为什么只有 1.9×？fp16 怎么保证稳定？
答法

1.9× 来自 allreduce 通信、视频解码的串行段、以及每卡 batch 减半后的利用率损失。fp16 稳定靠四件事：GradScaler 动态缩放、fp32 master weights、动作输出 upcast、梯度裁剪 10.0；再加时间端点裁剪。监控 GradScaler 的 scale 与 grad_norm，异常时先查 attention 全 mask 行。

陷阱：说“fp16 和 bf16 一样，只是精度低一点”。bf16 的指数范围与 fp32 相同，fp16 范围窄，才需要 scaler。

E 层 · 评测与实验

Q18
74% 这个结果可信吗？
答法

“点估计 74/100，Wilson 95% 区间 [64.6%, 81.6%]。可信度取决于协议：10 任务 × 10 episode、固定初始状态集、n_action_steps=1、10 步预热、relative 控制。它的精度足以区分“明显好/明显差”，但不足以支撑 3–5 点的改进结论；单任务 10 个样本更不能排名。”

陷阱：只报 74% 不报区间；或把区间写成 [63.0%, 83.2%]（与标准 Wilson 不符）。
Q19
为什么评测用 n_action_steps=1？不是很慢吗？
答法

为了对齐论文仿真协议：每步重规划，最大化闭环反馈，避免开环误差累积。慢是事实，评测是离线仿真，不受实时约束；用吞吐换可比性。真机上会选 5–20 或 RTC，因为 20 Hz 下每步跑 10 次去噪不现实。

陷阱：说“n=1 一定比 n=50 好”。两者是权衡；n=50 可能更连贯，也可能累积误差。
Q20
spatial_5 只有 30%，你怎么诊断？
答法

先看 10 个 rollout 视频，把失败分成四类：未到达、抓空/滑落、放错位置、超时。再看失败帧的观测与训练分布差异（物体位置、遮挡、腕部视角）。然后做单变量干预：①把该任务示范过采样；②提高该任务评测 episode 到 50 个确认不是噪声；③检查语言 grounding（换同义指令是否仍失败）；④用 16k checkpoint 看是否预算问题。只有定位到阶段，才谈改进。

陷阱：直接说“加数据/训久一点”。没有失败分类的改进是碰运气。
Q21
怎么做数据增强消融才不被质疑？
答法

固定施加密度（每样本变换数、概率、顺序），只切换变换池；启动时打印生效配置并可视化单样本，确认不是恒等；两臂同数据、同步数、同评测初始状态；样本量按功效算（检测 10 点差异约 257/臂），至少两个训练 seed；报告均值、区间与 seed 方差，不轻易说“显著”。

陷阱：A 组 1 个变换、B 组 3 个变换，然后把差异归因于“有没有增强”。

F 层 · 部署与研究判断

Q22
要让这个模型在真机 10 Hz 跑，你怎么办？
答法

先测瓶颈：视觉编码、10 步去噪、控制频率各占多少。然后组合优化：①增大 n_action_steps 或 RTC 降低重规划频率；②torch.compile/TensorRT、fp16/INT8；③异步双缓冲，推理与执行重叠；④减少 num_steps 或蒸馏少步模型；⑤降相机分辨率/帧率。不要只换小模型，那会改变任务能力。

陷阱：给一个没有测量依据的延迟数字。应说“项目未测，需先做 profile”。
Q23
如果给你 10 倍算力，你先做什么？
答法

按信息量排序：①预算阶梯 16k/32k/64k，画预算-成功率曲线，回答“差距是否只是训练量”；②四套件联合训练，检验单套件是否限制泛化；③失败诊断驱动的数据重采样（spatial_5）；④最后才是 LoRA/全量微调对照。不会先调超参，因为当前最大的不确定性是预算与数据，不是 lr。

陷阱：说“先上更大模型”。那会同时改变容量、数据与预算，无法归因。
Q24
SmolVLA 的上限在哪？什么时候该选 π0/OpenVLA？
答法

SmolVLA 的上限受 450M 容量、冻结骨干与社区数据限制；在单任务/少任务、消费级硬件、需要快速迭代时选它。若需要跨本体泛化、复杂语言推理、大规模多任务，π0（3.3B、跨本体）或 OpenVLA（7B、OXE、离散 token）更合适，但训练/推理成本高。选择应看“数据规模 × 延迟预算 × 硬件”，不是看榜单。

陷阱：说“小模型迟早全面取代大模型”。容量与泛化的权衡不会消失。
Q25
你认为 VLA 未来 1–2 年的关键问题是什么？
答法

四个：①数据：跨本体、可复用的动作数据仍稀缺，合成与视频预训练是方向；②评测：仿真与真机的相关性不足，需要标准化协议与统计报告；③延迟/可靠性：10 步去噪与闭环频率的矛盾，需要少步生成、异步与安全回退；④长程与记忆：当前 chunk 只覆盖 2.5 秒，多阶段任务需要层次化策略与记忆。我的项目正好在②③上提供了低成本基线。

陷阱：泛泛说“多模态大模型会解决一切”。要给具体瓶颈与可验证方向。
CHAPTER 21

白板推导：8 道必须能当场写出的题

白板题考的不是背诵，而是“从定义出发、符号不乱、收尾能解释”。每题给步骤与一句收尾话，练习时遮住答案自己写。

白板 1 · 流匹配损失

题：从 x_t=tε+(1−t)a 出发，推出训练目标，并说明为什么最优解是条件期望。

步骤

① 对 t 求导：dx_t/dt=ε−a。② 令网络输出 v_θ(x_t,t,c)，最小化 E‖v_θ−(ε−a)‖²。③ 对固定 (x_t,t)，逐点最小化 E[‖v−(ε−a)‖²|x_t]，对 v 求导令零，得 v*=E[ε−a|x_t]。④ 收尾：这是回归，不是 ELBO；训练一次采样 t,ε 即可。

白板 2 · 欧拉积分与符号

题：写出 NOISE_AT_ONE 下从 t=1 到 0 的 10 步更新，并用一维例子验证。

步骤

① Δt=−0.1，x_{k+1}=x_k+Δt·v_θ(x_k,t_k)，即 x−0.1v。② 一维：a=1,ε=−0.5,t=0.7，x=−0.05,v=−1.5，一步后 0.10，与解析解 t=0.6 的 0.10 一致。③ 收尾：线性路径下积分无离散误差，误差来自网络；符号写反会发散。

白板 3 · 掩码矩阵

题：att_mask=[0,0,0,1,1]，画出 5×5 可见矩阵并解释。

步骤

① cumsum=[0,0,0,1,2]。② 判据 c_j≤c_i：前三行只能看前三列；第 4 行看 0–3；第 5 行看 0–4。③ 收尾：前三 token 双向（图像/语言），后两 token 因果（状态/动作），前缀看不到后缀。

白板 4 · loss 分母

题：B=32、每样本 50 步、其中 3 条各 47 步 padding，求分母；若误用 mean() 会怎样？

步骤

① 有效步数 32×50−3×47=1459。② 分母 1459×7=10213。③ mean() 分母 11200，稀释约 9%；若连 32 维平均，分母 51200，稀释约 4.6 倍。④ 收尾：padding 是重复边界帧，不 mask 会学到静止动作。

白板 5 · KV cache

题：前缀 177、后缀 50、10 步；比较有无缓存的计算量，并估算 16 层、5 KV 头、64 维、B=10 的缓存显存。

步骤

① 无缓存每步 (227)²=51,529，10 步 515,290。② 有缓存每步 50²+50×177=11,350，10 步 144,829，约 3.56× 省。③ 显存 16×2×10×5×177×64×2B≈36MB。④ 收尾：前缀不到 200 token，缓存不是显存瓶颈；每步要 crop 回前缀长度。

白板 6 · token 预算

题：512×512、patch 16、pixel shuffle 4×4、两相机，算视觉 token；若不做 shuffle，注意力成本变多少？

步骤

① 每帧 patch 数 (512/16)²=1024。② shuffle 后 1024/16=64，两路 128。③ 不 shuffle 是 2048，前缀从 177 变 2097，序列约 12× 长，注意力约 144×。④ 收尾：64 是让 450M 模型在消费级卡上可训的关键。

白板 7 · Wilson 区间

题：74/100，求 95% Wilson 区间。

步骤

① p̂=0.74,n=100,z=1.96。② 中心 (p̂+z²/2n)/(1+z²/n)=0.7311。③ 半宽 z√(p̂(1−p̂)/n+z²/4n²)/(1+z²/n)=0.0848。④ 区间 [0.646,0.816]。⑤ 收尾：解释为“重复实验的区间覆盖率”，不是“真值概率”。

白板 8 · 样本量与配对

题：检测 74%→84% 的差异，80% 功效、α=0.05，需要多少样本？若两臂共用初始状态，如何更省？

步骤

① n≈(1.96+0.84)²[0.74×0.26+0.84×0.16]/0.1²≈257/臂。② 配对：同一初始状态做 A/B，比较不一致对，用 McNemar；任务难度方差被消掉，所需样本通常显著减少。③ 收尾：100/臂只能检测大差异，小改进必须扩样本或多 seed。

一页速查卡（面试前 10 分钟）

SmolVLA 一句话

450M = 冻结的 SmolVLM2 前缀（16 层、宽 960）+ 可训练动作专家（16 层、宽 720），流匹配生成 50×7 动作块，10 步欧拉。

关键数字

视觉：512²，patch 16 → 1024 → shuffle → 64/帧

前缀：2×64 + 48 + 1 = 177

后缀：50；总长 ≤227

专家：0.75×960=720；隔层 SA/CA

训练：8k updates，bs64，1e-4，warmup 2k，decay 32k

评测：10×10，n_action_steps=1，10 步预热

结果：74%，Wilson [64.6, 81.6]

预算：论文微调 100k → 1/12.5

四条必背推导

流匹配：x_t=tε+(1−t)a，v=ε−a，MSE 最优 = 条件期望

积分：Δt=−0.1，x←x−0.1v；符号反了就发散

掩码：cumsum，c_j≤c_i 可见；图像/语言双向，动作因果

loss：分母 = 有效步数 × 7，不是 B×50×32

五个高频陷阱

att_mask ≠ padding mask

专家不是第二个 VLM，没有词表

去噪时 VLM 不重跑，只读 KV cache

padding 是重复边界帧，不是补零

74% ≠ 复现 90%；协议/预算/数据都不同

三个 STAR 标题

T4 fp16 迁移：fp32 权重 + autocast + GradScaler + upcast

会话回收续训：全状态 checkpoint + Hub 备份 + 启动自检

74% 的可信化：Wilson 复算 + 预算口径修正 + 失败分类
